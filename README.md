# DSH Scoped Models · 模型范围

像 pi 的 scoped-models 一样，勾选常用模型，让 DSH **原生模型选择列表**只显示这些模型，而不是增加一个替代选择器。

## 使用

1. 安装并启用本目录的插件包。
2. 打开 **设置 → 模型范围**。
3. 搜索模型名称、ID 或提供商，勾选常用模型（可按提供商筛选、批量选中搜索结果）。
4. 直接调整模型勾选或默认思考等级，修改自动保存并立即更新原生模型列表，无需额外开关或保存按钮。
5. 关闭设置，使用输入框原生模型选择器或 `/model`。

默认只显示已选模型；取消全部选择时原生列表为空，设置页始终能查看完整目录并重新选择。已安装旧版本且关闭了过滤的配置，在首次打开设置页时自动启用，保留原有选择。配置按当前 DSH profile 保存，刷新、重启后保留，并作用于该 profile 的会话。保存中可继续调整，后续修改按顺序写入；失败会显示错误并保留草稿，点击「重试保存」可再次提交。

## Codex 订阅与动态模型

读取 DSH 当前运行时的完整 `sessionController.modelCatalog()`，不是内置模型表。所有 `codex-*` 多账号提供商在设置页合并为一个 **Codex** 组，按模型 ID 去重并展示各账号模型的并集，只需配置一次，选择就会对所有现有及后续登录的 Codex 账号生效。保存使用统一的 `provider: "codex"`；旧的分账号选择自动按并集合并，下一次保存时写入统一配置。

原生选择器仍保留各账号真实 provider ID、名称与模型能力，不改变请求路由。其他提供商（包括独立的 `openai-codex`）仍按 `(provider, model)` 精确匹配，不与 `codex-*` 混淆。

保留 Codex 插件自己的选择器、推理档位、Fast 等控件，只投影它所读取的原生目录。已被 Codex 插件自身「隐藏模型」移除的条目不会被强行恢复。退出账号后已选项会保留为暂不可用，恢复账号目录后再次可见；新增模型需要重新勾选，不会自动挤入常用列表。

## 默认思考等级

仅已勾选且支持思考等级的模型显示下拉框，分组标题右侧显示一次「默认思考等级」。选项来自提供商实际声明的 `reasoning.efforts`，不限于 Codex。修改自动保存后，未手动指定思考等级的调用使用该默认值；会话中已经显式选择的等级优先，不会被覆盖。

- 每个模型独立设置；`codex-*` 多账号共用同一份默认值。
- 取消勾选后隐藏下拉框，但保留已保存的等级；重新勾选时恢复。未选入常用范围的模型，其已保存默认等级仍可用于实际调用。
- 选择「跟随提供商默认」清除覆盖。模型暂不可用或已保存档位不再受支持时保留配置，但实际调用回退到该账号模型的默认值；可清除或重新选择。
- 不支持思考等级的模型不提供新的默认值设置。

## 边界与兼容性

- 不改 API Key、不改提供商、不卸载模型、不修改 session 的已存选择，也不包装 `llm.listModels`、`resolveModel` 或模型请求。
- 已有会话中未勾选的模型仍可执行；因原生 UI 只在当前目录中查名称，未勾选的当前模型可能显示为「选择模型」，切换到勾选模型后正常显示。
- 未选择模型或所选模型全部暂不可用时，原生目录为空；在设置里重新选择可用模型或重新登录账号即可。不自动放回未勾选的模型。
- Settings 的 revision 冲突会明确报错。自动更新串行提交，不会用较早的响应覆盖较新的勾选。刷新目录会等待当前更新结束，并保留失败后的草稿；错误不会无限重试。
- 当前 DSH **没有公开的 catalog-filter 或默认思考等级注册接口**。范围过滤只包装 `sessionController.modelCatalog`，保留未过滤目录供管理页使用；默认等级包装 `llm.normalizeModelInfo` 这一共同元数据校验出口，覆盖目录、能力查询及绑定 adapter 的 `prepareCall` 路径，后续仍由原生流程校验并填充请求控制，不包装请求发送方法。卸载/禁用时恢复原值与原 descriptor；若后来有插件包装同一方法，不覆盖它，而把已捕获的旧包装器转为透传。
- 当前运行环境：DSH `0.2.1-rc.5`、Codex Subscription `3.2.5`。升级 DSH 后若目录接口变更需重新验证；不复制或替换 DSH 的 UI 包。

## Agent 工具

`scoped_models` 与设置页共用 Host 操作：

- `action: "list"`，可选 `query`：返回完整目录的匹配项（最多 100 个）、保存范围及 revision。
- `action: "set"`：传入 `enabled: true`、完整的 `models: [{provider, model}]` 及读取时的 `revision`；`models: []` 表示不展示任何模型。`enabled: false` 仅作为兼容工具的临时恢复完整列表入口，设置页不提供该开关，重新打开设置页会恢复为仅显示已选。
- 可选 `reasoningDefaults: [{provider, model, effort}]` 完整替换默认思考等级；省略保留原配置，传 `[]` 清空。`effort` 必须使用 `list` 返回的 `reasoning.efforts` ID。

工具返回的 `truncated` 为 true 时用更具体的 query 缩小查询。设置操作只影响模型列表，不是权限控制。

## 开发与安装

```sh
pnpm install --ignore-scripts
node --test tests/*.test.js
node --check index.js
node --check client.js
```

### 初次安装验收（历史记录）

- 17 项核心/Host 集成测试通过，包括 UI RPC 与工具共用操作、revision 冲突、动态目录、精确提供商匹配和卸载恢复。
- 当前运行中的真实目录：415 个模型，其中 Codex 订阅提供 9 个。通过工具临时启用 Codex 与 OpenRouter 两个模型，原生 Host 目录从 415 收缩到 2；关闭后恢复 415。
- 测试后已恢复 `enabled: false, models: []`，没有替用户保存常用模型。
- 插件应用状态为 `applied`，无警告；设置页 `scoped-models` 已在现有 GUI 的 live Slot 注册。图标/中英文资源已检查。
- 当前会话没有浏览器点击/截图控制，实际页面布局、明暗主题与点击保存的视觉验收仍待用户确认；未将 Slot 注册当作视觉成功。

在 DSH 插件管理器中，以本目录的绝对路径安装本地包。不要手改 profile 文件。本地安装链接工作区，保持本目录存在；更新已安装的 JavaScript 代码后按 DSH 提示重新加载/重启，不能假设桌面端有开发 watcher。
